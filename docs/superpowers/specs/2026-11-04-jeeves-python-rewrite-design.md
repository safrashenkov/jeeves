# Дживс на Python: дизайн переписывания

Дата: 2026-11-04. Статус: **черновик на согласование**.

## Зачем

Дживс — Telegram-бот для игроков WoW (чаты гильдий). Старый код на PHP (`jeeves/` и `jeeves-test/`) почти весь мёртв: из живого осталась только рассылка RSS-новостей. Цель — переписать на Python и вернуть функционал по одной возможности за раз, проверяя на живых чатах. Старые проекты остаются как справочник, их не правим.

## Цели

1. Бот на Python, который работает на сервере и рассылает новости (паритет с тем, что жило).
2. Развёртывание описано инструкцией и повторяется одной командой/скриптом, без ручной магии.
3. Roadmap со всем старым функционалом (`ROADMAP.md`); реанимируем по приоритету, невозможное честно отмечаем «не оживляем».
4. Архитектура позволяет добавлять команду как отдельный модуль, не трогая остальные.

## Не цели

- Не переносим код 1:1. Берём поведение, а не реализацию.
- Не тащим мёртвое (аукцион, симы, «Ло», OAuth) в первый этап.
- Не меняем схему БД на первом этапе.
- Не делаем веб-интерфейс.

## Анти-цели (провал, даже если «технически работает»)

- Новости дублируются в чатах или после первого запуска приходит лавина старых новостей.
- Бот молча падает, и никто не замечает.
- Секреты попадают в репозиторий (старые «не актуальны», но новые токены держим только в `.env`).

## Решения пользователя

- БД остаётся прежней: MariaDB, база `wa`. Схема: `jeeves/schema.sql` (старого проекта). Для этапа 1 нужны `t_settings` и `t_chat_settings`.
- Начинаем с RSS-новостей и включения/выключения подписки.
- Вебхук: `https://jeeves.perm-bear.ru/...`
- Сразу готовим развёртывание и инструкцию.
- Roadmap со всем старым функционалом.

## Мои решения (проверь, это не согласовано)

## Поведение этапа 1

**Команды.** Сохраняем старый стиль: в группе бот реагирует на сообщение, начинающееся со слова «Дживс», в личке на любое. Дополнительно работают слэш-команды.

| Фраза | Слэш | Действие |
|---|---|---|
| «Дживс, включи новости» | `/news_on` | `t_chat_settings(chat_id,'enableNews','1')`, ответ «Подписка на новости включена» |
| «Дживс, выключи/отключи новости» | `/news_off` | значение `'0'`, ответ «Подписка на новости отключена» |
| «Дживс, помощь» | `/help`, `/start` | текст со списком доступных команд (только оживших) |

Команды регистрируются в реестре (фраза → обработчик), чтобы новые добавлялись отдельным модулем. Незнакомая фраза пока получает вежливый отказ, а не случайную реплику.

**Новости.**
- Раз в 5 минут бот опрашивает ленты и берёт записи с `pubDate` строго больше `newsUpdateTime` из `t_settings`, как раньше.
- Источники из старого кода: noob-club, MMO-Champion, два YouTube-канала (`UC7Oo1q9m4vf7XrlZgOR95WA`, `UCbLj9QP9FAaHs_647QckGtg`), Wowhead news, Raider.IO. Twitter-ленты через twitrss.me не восстанавливаем, они мертвы. Каждый источник проверяем при реализации и отключаем, если не отвечает. Падение одной ленты не ломает остальные.
- Формат сообщения прежний: заголовок и ссылка, HTML, предпросмотр ссылки включён.
- Сообщения отправляются в чаты, где `enableNews = '1'`. Между отправками небольшая пауза (лимит Telegram), записи рассылаются от старых к новым.
- Если Telegram вернул «бот заблокирован» или «чат не найден», чат автоматически получает `enableNews = '0'`. Если чат перенесён в супергруппу, ID обновляется.
- `newsUpdateTime` обновляется только после рассылки.
- **Защита от лавины:** у существующего значения `newsUpdateTime` неизвестный возраст. Если оно старше 24 часов, при старте оно сбрасывается на «сейчас», и старые записи не рассылаются.

**Админ.** `ADMIN_ID` из `.env`. На этапе 1 админ-команд нет, только лог ошибок в чат админа.

**Эксплуатация.**
- Логи в stdout (читает journald). Ошибки рассылки уходят админу в личку, не чаще раза в час.
- Эндпоинт `/healthz` для проверки.
- Вебхук ставится при старте через `setWebhook` с `secret_token`, который проверяется на входе.

## Развёртывание (что будет в `DEPLOY.md`)

1. Требования: Python 3.12, nginx, доступ к MariaDB, сертификат для `jeeves.perm-bear.ru`.
2. Создать пользователя и каталог, клонировать/скопировать код, создать venv, поставить зависимости.
3. Заполнить `.env` (токен бота, доступ к БД, секрет вебхука, `ADMIN_ID`).
4. Подключить `nginx.conf` (TLS, проксирование на локальный порт), включить systemd-юнит.
5. Проверка: `/healthz`, `getWebhookInfo`, тестовое сообщение в чат.
6. Обновление и откат. Остановка PHP-версии, чтобы два бота не слали новости одновременно.

## Что оставлено исполнителю

- Точная библиотека для разбора RSS (`feedparser` предпочтительнее).
- Структура таблицы логов ошибок, если понадобится (на этапе 1 не нужна).
- Способ отметить в БД чат как заблокировавший бота, кроме `enableNews = '0'`.

## Ответы пользователя (2026-11-04)

- Сервер: nginx уже есть, **Docker не нужен и не используется**, сертификаты для `jeeves.perm-bear.ru` есть, бот работает на том же сервере, что и MariaDB (`127.0.0.1`). Значит `systemd` + venv + nginx, как и планировалось.
- Включать и выключать новости может **любой участник чата** (как раньше).
- Репозиторий git создан в `jeeves-py`. **Коммиты только по явной просьбе пользователя.**

## Открытые вопросы

1. **Токен бота:** старый бот или новый? Если старый ещё привязан к PHP-вебхуку, `setWebhook` переключит его, и PHP-версия перестанет получать апдейты. Не блокирует код и тесты; нужен до первого развёртывания. По умолчанию в плане: токен читается из `.env`, `DEPLOY.md` описывает оба варианта.
